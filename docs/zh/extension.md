# Chrome 扩展

本地 Manifest V3 扩展包，与网页版共用编辑器。扩展包版本 0.1.0 是安装清单版本，尚未发布到商店。

## 安装

1. 开发时运行 `npm ci` 和 `npm run build:extension`。
2. Chrome 打开 `chrome://extensions`，开启开发者模式。
3. 点击“加载已解压的扩展程序”，选择项目的 `dist-extension` 文件夹。ZIP 需先解压，不能直接加载。
4. 在扩展菜单固定 Notepad，点击图标打开完整编辑器标签页；无需本地服务器。

升级时重新构建，在扩展管理页点击刷新。**先保存所有编辑内容**，然后重新打开编辑器。保持同一目录加载以保留扩展身份；移除扩展或切换身份可能丢失主题设置。

## 使用与权限

- 点击图标每次打开一个独立编辑器页面，避免覆盖已有未保存内容。
- 网页选中文字后右键“在 Notepad 中编辑选中文字”，在新标签页生成未保存文档，再用现有双文本对比功能选择另一个文档。
- 选中文字最多 1 Mi UTF-16 单元，不截断。失败会打开错误提示页。无内容脚本、无网站访问权限，也不读取网页全文或 URL。
- `contextMenus` 提供右键菜单；`storage` 仅用于选中文字的临时传递。随机 ID 位于 URL，正文不进入 URL；正文存入 `chrome.storage.session`，成功导入即删除。10 分钟后不再接受，在下一次发送时清理过期数据，浏览器结束会话后清除。多个请求串行入库，各自使用独立 ID。
- 主题仍使用扩展页面 localStorage，与网页版隔离；用 JSON 导入导出迁移。正文不自动保存，关闭页面前需保存。
- 文件访问仍需用户选择文件。超大文件限制与网页版相同，扩展不会自动扩大内存或获得任意磁盘权限。

## 架构与维护

`extension/manifest.json` 定义最小权限和 CSP；`src/extension-background.ts` 只负责入口和传递；`src/extension-handoff.ts` 校验载荷和确认清理。大文件与正则任务仍在编辑器页面的 Worker 中运行，不在后台 service worker 中运行。

`npm run build:extension` 将编辑器、两个 Worker、后台脚本和生成的 PNG 图标写入 `dist-extension/`。依赖全量打包，无远程代码；CSP 限制脚本/Worker 为本扩展，禁止网络连接。`npm run build` 仍产生普通网页。

## 验证边界

本次完成 TypeScript、20 项单元测试、网页与扩展构建、扩展产物检查。新增测试覆盖过期/超限/异常载荷、网页隔离与导入确认清理。`npm run check:extension` 可重复检查产物。

**尚未在 Chrome 实际加载扩展**；工具栏入口、原生右键菜单、扩展 origin 下 Worker/CSP、原生文件保存仍需安装后验收。先前网页 100 MiB/1 GiB 搜索证据不能直接视为扩展验收。没有商店发布或 PWA 安装支持。

安装后验收：点击图标；右键导入中文/emoji（确认文本无损）；查找替换及 JSON 格式化；主题切换后重开；导入大文件并全局查找/取消；验证另存文件与源文件内容。记录 Chrome 版本及结果。

依赖检查发现现有 Vitest 3 开发工具链有 3 项 npm audit 告警（不打包到扩展）；未在此改造中跨大版本升级测试框架。
