## 分层与数据流

```text
界面：标签页 / 编辑区 / 对比区 / 查找面板 / 状态栏 / 主题管理
                         ↓ 用户意图
应用层：文档会话 / 命令与撤销 / 任务调度 / 能力检测
          ↓                     ↓                 ↓
普通编辑适配器             大文件任务 Worker       主题服务
内存文档、语法、diff       解码、稀疏行索引          JSON 校验
JSON 与文本工具            搜索、替换变换           主题令牌映射
          ↓                     ↓                 ↓
文件服务：读取 / 保存 / 流式输出               localStorage
```

普通文件使用成熟编辑组件的适配层；大文件只把当前窗口文本交给视图，不创建全文编辑模型。两者共享文件元数据、主题、查找界面和任务状态，但分别声明可用功能。

## 文档与任务状态

文档保存稳定 ID、名称、来源引用、模式、编码、BOM、换行情况、修订号、修改状态及视图位置。原始字节与解码后的文本有不同坐标系；索引必须保存可安全重新解码的字节位置和逻辑行号。

普通文档：打开 → 就绪 → 修改 → 保存中 → 就绪/修改状态保留并报错。保存成功才清除修改标记。切换到大文件模式前不得丢弃未保存内容。

后台任务：空闲 → 运行 → 取消中 → 已取消，或运行 → 完成/失败。消息至少包含 `taskId`、`documentId`、`revision`、操作类型、阶段、已处理字节、总字节。主线程丢弃旧任务/旧修订结果。任务进度、完成、错误分开传递，不能用“已处理 100%”代替写入关闭成功。

## 大文件内存与正确性

输入块、输出队列、视口缓存和搜索结果窗口均设置上限。输出使用背压，避免 Worker 生成速度超过磁盘写入速度。索引按间隔采样并设置预算，不能为每行无限追加内存记录。超长单行需分段展示，不能依赖“逐行读入”保证内存有界。

固定文本匹配保留跨块必要状态；替换从左到右采用非重叠匹配，不重新扫描替换结果。字节进度按输入统计，输出长度可以不同。取消时停止读写并清理未完成输出；不得把残留文件标成完成。详见[大文件规格](features/large-files.md)。

## 普通文本工具与 diff

耗时计算放入可终止任务；禁止不受控正则阻塞主线程。diff 合并必须针对计算时的文档修订号，过期时重新计算，不使用过期偏移写入。一次合并对应一次撤销事务。忽略规则只影响比较，不擅自规范化原文。

JSON 工具应保留大整数和精确数字词法；不能直接假设 parse/stringify 无损。重复键必须检测并说明处理策略，首版优先保留原文并报错，不静默丢弃键。格式化失败不得覆盖原文。

## 存储与兼容

主题 JSON 经过白名单校验后映射到界面及编辑器令牌，不接收任意脚本、CSS 或远程资源。localStorage 只放主题和小型偏好，不放大文件或全文。草稿恢复另行设计。

按能力检测选择保存方式：有流式磁盘输出能力才开放超大结果导出；无该能力时仅允许经过大小约束的小结果下载。权限拒绝、磁盘不足、编码失败都必须保留原文件并提供可理解错误。兼容浏览器和实际 API 待技术验证。

## 当前实现选择

采用 Vite + TypeScript + CodeMirror 6；实际模块见[开发指南](development.md)。CodeMirror 提供编辑状态、撤销和双文本差异基础；大文件不进入它的全文模型。普通正则放入可终止 Worker。初版采用字节窗口，不实现稀疏行索引，避免未经验证的行索引开销。

参考：[CodeMirror 官方 API](https://codemirror.net/docs/ref/)、[File System 标准](https://fs.spec.whatwg.org/)。两者在实现阶段查阅，具体支持以本项目验收为准。
